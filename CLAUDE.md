# Character Runner — notes for Claude sessions

Offline-first D&D 2024 character sheet (static PWA on GitHub Pages, no build step, no accounts).
Characters live only in each player's browser storage; the repo holds the app and the rules data.

## The rules data is password-locked
- `data/library.enc.json` is the only copy of the rules in the repo (AES-GCM, key from the group password via PBKDF2). Book text must never be committed readable.
- `data/library.json` (readable) is gitignored. Never `git add -f` it. Before committing, `git grep -I "Celestial Resistance"` should find nothing.
- The password is never stored in the repo, in memory files, or in any file. Ask the user for it each session.
- To edit rules: `CR_PASSWORD=<from user> node tools/crypt.mjs unlock` → edit `data/library.json` → `CR_PASSWORD=<same> node tools/crypt.mjs lock` → commit only the `.enc.json`.
- Locking with the same password keeps the salt, so players' devices update silently. A new password makes every device ask once.
- `data/campaign.json` (DM allowlist + homebrew) and `data/seed-gandork.json` are the user's own content and stay readable.

## Button law
One standard for every control; the BUTTON LAW block at the end of `css/styles.css` is the only place it lives. Actions are `.btn` (+ `pri` | `danger` | `ghost`, `sm`): Cinzel, uppercase, .8rem (sm .72rem), 44px (sm 36px), `--radius-sm`. Icons are `.iconbtn`; choices are `.optcard`, `.chipbtn`, `.seg button`. Press = 90ms: small controls `scale(.95)`, wide surfaces (rows, cards, tiles) `scale(.99)`, text links fade; all get `brightness(.94)`. Hover changes the border only (no lift, no shine). One focus ring, one disabled look (.4 opacity). Do not set `min-height` or `font-size` on a `.btn` in a component rule; add a size to the law instead. Watch for class collisions: a `.sm` description cell once shrank every `.btn.sm`. Enforced by the e2e check "Button law" (sizes, label style, a press on every kind of button, on phone width).

## Idiot-proofing
`store.readRoster` keeps only well-formed entries and `normalize` runs `prep` first, which coerces wrong types (names to text, scores/HP/coins to bounded numbers, lists to arrays). Add a coercion there when a new field is read with `.map`/`.toLowerCase`/arithmetic. `parseImport` accepts only objects with a name and abilities. `index.html` swaps in memory storage when the browser blocks it (`window.__memStore`; Home shows a banner). Tours: `js/tour.js` (state `dnd-tour-v1`, overlay in `#tour-root` outside `#app`), copy in `js/tourdata.js` (content file, not copy-linted; titles under 5 words, bodies under 30). Finishing a tour unlocks the Silver accent. Hostile checks live in e2e ("Hostile storage", "Small phone", "Tours").

## Storage safety
`js/storagerisk.js` (pure) reads the device (`deviceInfo`: iPhone/iPad/Mac/Windows/Android, Safari/Chrome/Firefox/Edge/Samsung, installed or tab) and `assess` gives a level (high | medium | low), headline, reasons and steps; its wording is content, not copy-linted, and must never promise safety (tested). Facts it rests on: WebKit deletes a Safari tab's script-writable storage after 7 days of Safari use without visiting (Home Screen apps exempt; every iPhone browser uses WebKit), `persist()` is honoured by Chrome/Safari by heuristic and by Firefox via a prompt, Chromium rarely evicts but users clear data, silent file auto-save exists only in Chromium so backups stay manual. The explainer modal `storage` opens once on first Home (`dnd-storage-intro-v1` set only by "I understand"; closing with X shows it again next launch; never under automation); `persist()` is requested only after that acknowledgement. Deleting a character: typed name (checked in the action too), "Save a copy first", then `js/trash.js` (`dnd-trash-v1`, 30 days, max 8, drops oldest under quota) and Roster > Recently deleted > Restore. Tests: `tests/storage.test.mjs`, e2e "Storage safety". `node --check` does not catch duplicate imports: import every module in Node (see the loop in the Before pushing step) before running the browser.

## UI copy (what "AI talk" is, and how to avoid it)
**Definition.** AI talk is interface text that explains, reassures or converses instead of labelling. Test: delete the sentence; if the screen still works, it was AI talk. Seven tells, all checked by `tools/copy-lint.mjs` (run by `node tests/copy.test.mjs`, must stay at zero):
1. **tutorial** - tells how to use the screen ("Tap a card to ..."). The control must look usable; if it does not, fix the design.
2. **reassure** - "Don't worry", "nothing is lost", "safe", "for now".
3. **hedge** - simply, just, easily, a bit, actually, please.
4. **marketing** - "!", powerful, perfect, ready to, welcome, special.
5. **chatty** - asides with dashes, "you'll", "we", "let me", "would you like".
6. **narrating** - the screen describing itself ("this screen lets you", "the app reads").
7. **sentence where a label fits** - button/label over 4 words, toast over 9, any text over 12 words ending in a period; "you can ..." permission statements.
**House style.** Noun or verb labels (Create, Edit, Reroll, Export). Toasts are a result, not advice ("Link copied"). Numbers and states over prose ("0/2", "Locked"). Aria labels name the thing and its value ("Hit points 12 of 20"), never the gesture. Destructive confirmations get one short sentence naming the object and the consequence. Errors: cause, then remedy, 8 words max. Book rules text stays in the rules file and is never edited for tone.
**Plan.** (1) New or changed visible text must pass `tests/copy.test.mjs` before commit. (2) Write the label first, add a sentence only if a user would get hurt without it. (3) If a screen seems to need a tutorial, change the layout instead. (4) Extend the rules in `tools/copy-lint.mjs` when a new tell shows up (each rule has a one-line reason). (5) Review copy on a screenshot at 390px, not in code.
